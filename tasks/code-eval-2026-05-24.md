> This is the dated **snapshot**. The reusable harness that produced it lives at [`evals/`](../evals/) — run `./backend/venv/bin/python evals/run_code_eval.py` (with proxy creds loaded) after any prompt change to catch regressions.

## Method & caveat

- **What this is:** a structured eval over 18 **realistic raw transcriptions** (the garbled Whisper output a code-editor dictation produces, EN + DE, short→long), each pushed through the live `_CODE_SMART` prompt via the proxy (Claude/landa_proxy). Judged candidate-vs-baseline on the §7 criteria: correctness (no invented facts/logic), tokens/format correct, tone-fit, and the two code-specific guards (never answer/execute; don't over-correct "cloud").
- **What this is NOT:** a true blind A/B on Nick's own recorded audio rated by a human. That still wants doing with real audio — this automated pass surfaces regressions and confirms behavior, but the human blind A/B is the final sign-off.
- **Baseline** = the raw transcription itself (what you'd paste with no polish). **Candidate** = the prompt output.

## Findings / tuning notes (minor — not blockers)

1. **Operator strictness (OP1):** spoken "equals" became `===` (strict). Idiomatic for a boolean compare, but the speaker may have meant `==`. The prompt only maps "equal equal"→`==` / "triple equals"→`===`; a bare "equals" is the model's judgment. Acceptable; watch in the human A/B.
2. **Markdown backticks/tags in non-markdown targets (OP2, K3, LONG1):** output sometimes adds inline `` `code` ``, `<artifact>`, `` `/users` ``. Helpful in an agent prompt or a Markdown doc, but if pasted into a plain commit message or a `.py` comment those characters are literal. Low-frequency; consider whether to strip inline backticks for non-Markdown editors later.
3. The earlier-seen casing-scope nits (trailing "snake case" left in; unprompted fusion of "total price") did **not** recur in this corpus, but the corpus didn't stress them hard — keep them on the human A/B list.
