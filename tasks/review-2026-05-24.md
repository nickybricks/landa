# Production-Readiness Review — Landa — 2026-05-24

**Scope:** all dimensions (security, reliability, performance, maintainability, UX)
**Stack:** Cross-platform Electron 33 app + local Python/Flask backend over HTTP on `localhost:7890`; voice-to-text (local whisper.cpp or OpenAI API) → reformat → paste.
**Reviewed against:** `e4ac7a1` (working tree dirty: `tasks/todo.md`, untracked `LANDING.md`, `archive/`)

---

## Top-line findings

1. **[Security] `backend/landa_core.py:2903-2935`** — `GET/POST /config` on the localhost backend has no auth and no CORS/Origin check; any local process or even a visited website can read the stored OpenAI API key or repoint the backend at an attacker proxy. **Highest-leverage fix.**
2. **[Reliability] `backend/landa_core.py:2908-2935`** — `POST /config` does an unlocked read-modify-write on the global config under Flask `threaded=True`; concurrent writes (tray + settings + mode-select) silently drop each other's changes. Same endpoint as #1.
3. **[Reliability] `main.js:1367-1376`** — Backend crash-restart loop has no cap or backoff; a persistent failure (revoked mic permission, port bound, bad model) respawns every 2s forever with no user-visible error.
4. **[Security] `.env:2` / `backend/landa_constants.py:14`** — `LANDA_APP_SECRET` is one shared bearer token baked into every shipped binary; trivially extractable, lets anyone run unlimited LLM calls on Landa's bill.
5. **[Performance] `backend/landa_core.py:2393-2394` + `landa_streamer.py:119`** — On the default local-transcription path, `language:"auto"` runs a full detect pass *then* a full transcribe pass over the whole recording — roughly doubling the stop→paste wait the user stares at.
6. **[UX] `renderer/settings.js:790-799`, `986-991` + no `:focus-visible` anywhere** — Sidebar nav and shortcut-rebind controls are click-only `<div>`s and focus is invisible app-wide; the settings window is largely unusable by keyboard / screen reader.
7. **[Maintainability] `landa_core.py:1990` & `:2080`** — The two transcription-finalize paths re-implement the same post-process→reformat→paste→history pipeline and have already drifted; combined with zero tests on the three largest files, any change to the core flow is an uncatchable regression risk.

## Security

### High (likely exploitable or sensitive data exposure)
- `backend/landa_core.py:2903-2935` — The local backend exposes `GET /config` (returns the full config, including the user's OpenAI `api_key`) and `POST /config` (arbitrary config writes) with **no authentication and no CORS restriction**; any local process — or any website the user visits, via a DNS-rebinding / no-preflight form POST to `127.0.0.1:7890` — can read the stored API key or repoint the backend at an attacker-controlled proxy. — **fix:** require a per-launch bearer token (generated by main.js, passed to the spawned backend and to every renderer request) on all routes, and reject requests whose `Origin`/`Host` header isn't the expected localhost value.
- `.env:2` / `backend/landa_constants.py:14` — `LANDA_APP_SECRET` is a single shared bearer token baked into every distributed binary that authenticates the whole user base to the Landa proxy; it is trivially extractable from the shipped PyInstaller binary, so any user can lift it and run unlimited LLM calls on Landa's bill. — **fix:** issue per-install/per-user credentials from the proxy (or short-lived signed tokens) instead of one global secret embedded in the client.

### Medium (defense-in-depth)
- `main.js:1559,1565,1594` — macOS app-icon extraction interpolates filesystem-derived paths (`icnsPath`, `appPath`, `plistPath`) into `execAsync` (a shell), so a `.app` bundle in `/Applications` whose name contains a `"` or `;` yields shell command injection when the app list is built. — **fix:** use `execFile`/`spawn` with argv arrays (no shell) instead of `exec` with interpolated strings.
- `renderer/settings.js:2403` — User-entered "linked URLs" are interpolated into `innerHTML` without escaping, so a typed value like `<img src=x onerror=...>` executes script in the (sandboxed, but app-privileged) settings renderer. — **fix:** wrap `url` in the existing `escapeHtml()` helper.
- `renderer/settings.js:2431-2436` — OS-supplied app names are interpolated into `innerHTML` (and a `data-name` attribute) without escaping in `buildGridHtml`, allowing stored XSS via a maliciously named installed app. — **fix:** run `appItem.name` through `escapeHtml()` and quote/encode the attribute.
- `backend/landa_core.py:2279,2293,2619` — Downloaded whisper/LLM model `.bin` files are fetched over HTTPS but with **no checksum or signature pinning** before being loaded and executed by whisper.cpp; a HuggingFace account/CDN compromise yields code/model substitution. — **fix:** pin and verify a SHA-256 for each model artifact after download.

### Low
- `main.js:1229-1232` — The feedback window's `setWindowOpenHandler` passes any link to `shell.openExternal` without scheme validation; a link rendered by the remote Tally form could open `file://`/other dangerous schemes. — **fix:** allow only `https:`/`mailto:` before calling `openExternal`.
- `main.js:1748-1793` — IPC handlers (`save-config`, `patch-config`, etc.) don't validate `event.senderFrame`; harmless today (renderers load only bundled local files) but becomes a foothold if any window ever loads remote content. — **fix:** add a sender-origin allowlist check at the top of state-changing IPC handlers.
- `backend/requirements.txt:1-15` — Python dependencies are pinned with `>=` and there is no lockfile or hash pinning, so production backend builds are not reproducible and are exposed to a malicious upstream release on the auth/parsing/crypto perimeter (`flask`, `cryptography`, `huggingface_hub`). — **fix:** generate and commit a hash-pinned lockfile (e.g. `pip-compile`/`uv lock`) and build from it.
- `backend/landa_core.py:2858-2859` — `transcribe_openai` logs the raw exception (`print(... {e})`), which for some OpenAI client errors can include request context; combined with stdout being written to `backend.log` (`main.js:1357`) this risks secret/PII leakage into a plaintext log. — **fix:** log a sanitized message, not the raw exception object.

## Reliability

### Critical (will cause data loss, hangs, or crashes in production)
- `backend/landa_core.py:2908-2935` — `POST /config` mutates the module-global `config` (`config.update(data)`, nested `setdefault().update()`) with **no lock**, while Flask runs `threaded=True`. The tray menu (`main.js:793`, `806`), settings auto-save, `save-config-sync`, and `/modes/select` can all hit this endpoint concurrently. Two overlapping writes interleave the read-modify-write on the same dict and the last `save_config` wins, silently dropping the other's changes (e.g. a vocabulary edit racing a style toggle). — **fix:** guard `update_config`, `select_mode`, and any other `config`-mutating endpoint with a single `threading.Lock` (the existing `_history_lock` pattern), serializing the merge+`save_config`.
- `main.js:1367-1376` — backend crash-restart loop has **no failure cap or backoff**. On a persistent failure (mic permission revoked → `os._exit(2)` at `landa_core.py:1709`, missing model, corrupt binary, port already bound), `exit` fires → unconditional `setTimeout(startBackend, 2000)` → crash → repeat forever every 2s. This thrashes CPU, spams logs, and the user sees no error. — **fix:** track consecutive crashes within a window; after N (e.g. 5) fast failures, stop restarting and surface a dialog/tray error. Add exponential backoff between attempts.

### High (degraded behavior under load or partial failure)
- `main.js:1381-1387` — `stopBackend()` calls `backendProcess.kill()` (SIGTERM) but never waits for exit and never escalates to SIGKILL. Flask's `app.run()` installs no SIGTERM handler, and audio teardown can wedge inside CoreAudio (comments at `landa_core.py:1700-1709` document PortAudio hanging on `abort()/close()`). If the backend is mid-teardown on quit, SIGTERM may not reap it, leaving an **orphaned process holding the mic**. On Windows, `kill()` does not kill a child tree. — **fix:** in `will-quit`, send `kill()`, then after a short timeout force `kill('SIGKILL')` (Windows: `taskkill /pid <pid> /T /F`).
- `main.js:439-514` — the hotkey re-entrancy guard sets `hotkeyInFlight = true` then `await api.stopRecording()` (35s timeout). A genuinely wedged backend leaves the user unable to start a new recording for up to 35s with no UI feedback. — **fix:** show a "processing/stuck" state in the pill when a stop exceeds a few seconds, and ensure `forceStopRecording` can't stack.
- `backend/landa_core.py:2964-2978` — `/stop` blocks the HTTP worker on `_transcription_ready.wait(timeout=30)`. Because `_transcription_ready`/`_transcription_text` are process-global and `clear()`/set without a lock, a second `/stop` racing the first can `clear()` the event the first is waiting on, so the first returns `text=None` and **the transcription can be dropped** on a fast double-stop. — **fix:** serialize stop/transcription handoff with a per-request token or a lock, not shared globals.
- `main.js:1764` — `save-config-sync` writes config to disk then fires `api.saveConfig(cfg).then(...).catch(() => {})` as a floating promise during `beforeunload`. The window may be torn down before the POST completes, so the backend's in-memory `config` can stay stale until the next disk reload. — **fix:** on next backend `GET /config` re-read disk if the in-memory copy is older, or reload config from disk on a known-stale signal.

### Medium (resilience gaps)
- `main.js:2114-2150` — startup assumes the backend is reachable after a fixed `setTimeout(..., 2000)`; there is **no readiness probe**. On a slow machine the backend isn't up at 2s, and `/status` polling silently swallows all errors (`main.js:1508`) so "still booting" is indistinguishable from "dead." — **fix:** poll `GET /status` with a bounded retry loop until it answers (or a deadline), then apply config.
- `backend/landa_core.py:3324-3326` — `app.run(host=..., port=7890, threaded=True)` is the Werkzeug dev server with no graceful shutdown, no SIGTERM handler, no in-flight draining; a running `/stop` transcription is dropped on quit and the mic stream isn't closed. — **fix:** register an `atexit`/signal handler that aborts+closes any active stream; consider a production WSGI server.
- `main.js:1249-1255` — `startAudioLevelPolling` runs `GET /audio-level` every 80ms with the default 5s timeout. If the backend stalls, requests pile up (~60 concurrent sockets) with all errors swallowed. — **fix:** gate the next poll on the previous completing (recursive `setTimeout`), use a short (~1s) timeout.
- `backend/landa_core.py:480-484` — `_save_history` writes `HISTORY_PATH` with a plain `open(...,"w")` + `json.dump` (no atomic temp+`os.replace`, unlike `save_config`). A crash mid-write leaves a **truncated history.json**, which is then silently reset to `[]` on next load (`:475-476`), losing all history. — **fix:** use the atomic write-temp-then-`os.replace` pattern.
- `main.js:1352-1361` — backend stdout/stderr handlers append to `backend.log` but nothing surfaces a startup failure (ImportError, port-in-use) to the user; combined with the silent restart loop, a hard-failing backend is invisible. — **fix:** detect repeated early exits and show a one-time actionable error.

### Low
- `main.js:684-707` — `handleVocabHotkey` clears the clipboard, issues Cmd+C/Ctrl+C, waits 150ms, then restores. If `clipboard.readText()` throws, the user's clipboard can be left cleared. — **fix:** wrap the post-copy read+restore in try/finally so `prevClipboard` is always restored.
- `backend/landa_core.py:1633-1641` — the realtime WS thread catches all exceptions and sets `_rt_error`, but the recv loop at `:1620-1631` loops without a deadline, so repeated non-matching events could exceed the 35s join timeout (`:2003`) and leak the socket. — **fix:** bound every recv with a deadline, not just `settimeout`.
- `main.js:223` — `apiRequest` has no retry for transient `ECONNREFUSED` during backend boot; callers each implement ad-hoc swallowing. — **fix:** optional thin retry-with-backoff wrapper for idempotent GETs only (`/status`, `/config`).

## Performance

### Critical (user-visible jank, hangs, or OOM in normal use)
- `backend/landa_core.py:2393-2394` and `backend/landa_streamer.py:119` — On the latency-critical local transcription path (`landa-base`, the default), when language is `"auto"` the model runs `auto_detect_language(audio)` over the **entire** recording, then `transcribe(audio)` runs a **second full pass** over the same audio. This roughly doubles local transcription time — the single longest segment of the stop→paste wait. — **fix:** run one pass with `language=None` and read the detected language from whisper.cpp's transcribe result, or restrict auto-detect to the first ~3-5s slice.

### High (degrades meaningfully at moderate scale)
- `backend/landa_core.py:470-498` (`add_history_entry`) — Every transcription reads the **entire** `history.json`, `insert(0, …)`, and rewrites the whole file with `json.dump(indent=2)`. History is **never capped** (`/history` at `:3300` returns all of it), so cost grows linearly with total history, inside `_history_lock` at the tail of the paste pipeline. — **fix:** cap history (newest N≈500-1000) on write; truncate in `_save_history`.
- `renderer/settings.js:2748,2752-2834` (`fetchHistoryCache` → `renderHistory`) — `GET /history` returns the full unbounded history; `renderHistory` builds a DOM node per entry with `innerHTML` + 3-4 listeners each, no virtualization. At thousands of entries the History tab freezes the window. — **fix:** paginate/limit the backend response (last ~200) and/or virtualize.
- `main.js:1551-1576` (`getInstalledAppsMac`) — Spawns 2-3 subprocesses (`sips`, `plutil`/`qlmanage`) **per app, all at once** via `Promise.all` over every `.app`. On 150+ apps that's 300-450 concurrent spawns in one burst (renderer caches 5 min, bounding frequency but not the burst). — **fix:** cap concurrency (~8) and persist converted icons to disk keyed by app path+mtime.

### Medium (wasted work, modest impact)
- `main.js:1249-1255` (`startAudioLevelPolling`, 80ms) — During recording the renderer drives a full IPC→main→HTTP `GET /audio-level` ~12.5x/sec, each spawning a Flask worker. Redundant chatter for a value the backend already has. — **fix:** push levels over the existing socket (SSE/WS), or poll once in main and fan out.
- `main.js:1352-1361` — stdout/stderr handlers call `appendLog` per chunk, doing `fs.statSync` + `fs.appendFileSync` (two sync FS ops) on the main thread for each line. — **fix:** buffer log writes and flush on an interval, or use an async append stream.
- `backend/landa_core.py:1433-1439` (`apply_vocabulary_replacements`) — Recompiles a fresh regex per vocab + brand entry on every transcription, on the paste hot path. — **fix:** precompile a single combined alternation regex when config/vocab changes.

### Low (micro-optimizations)
- `renderer/settings.js:3131,3139` (`computeStats`) — `Math.max(...wordCounts)` spreads the full array as args; risks stack limits on large history. — **fix:** use a loop/`reduce`.
- `main.js:1458` (`applyConfig`) — `JSON.stringify(newModes) !== JSON.stringify(modesConfig)` serializes both objects to diff on every config apply. — **fix:** compare a version counter or shallow-compare known keys.

## Maintainability

### High (will block onboarding or cause regressions)
- `backend/landa_core.py:1990` and `:2080` — `_finalize_transcription` (realtime path) and `_transcribe_and_paste` (standard path) independently re-implement the same pipeline: `post_process` → `apply_lexicon_correction` → `reformat_text` → `paste_text` → usage/cost → `add_history_entry`. The copies have already drifted (one sets `prep_latency_ms: 0`, the other a real value; usage construction differs). — **fix:** extract a single `finalize_text(text, transcribe_usage, prep_latency_ms)` helper both paths call.
- `renderer/settings.js:1927` + `backend/landa_core.py:606` — the mode/category taxonomy is defined twice with no shared source (`MODES_CATEGORIES` vs `MODE_SYSTEM_PROMPTS`), and the "notes & code use `smart`, else `formal`" default is hand-coded in `defaultStyleFor`/`stylesForCategory` (settings.js:1999/1995) *and* `get_mode_prompt` (landa_core.py:964). Adding a category requires lockstep edits in two languages. — **fix:** make the backend the single owner of the category→styles→default map; have the renderer fetch it (extend `/config` or add `/modes/schema`).
- `main.js` (2175 LOC), `renderer/settings.js` (3176 LOC), `backend/landa_core.py` (3326 LOC) have **zero automated tests**. The only test file is `backend/tests/test_lexicon.py`, exercising a feature that isn't user-reachable (see below). The load-bearing record→transcribe→reformat→paste path and config `_migrate` (`landa_core.py:229`) are untested. — **fix:** add unit tests for isolatable pure logic — `_migrate`, `get_active_category`, `get_mode_prompt`, `_calc_cost` — before the next `landa_core.py` refactor.

### Medium (slows iteration, increases bug rate)
- `backend/landa_core.py:759` (`REFORMAT_PROMPTS`), `:3014` (`get_modes`), `:3023` (`select_mode`), `:3035` (`api_reformat`), `main.js:241` (`api.selectMode`) — the superseded "default/email/slack" mode system. `api.selectMode` is called by nothing; `/modes`, `/modes/select`, `/reformat` are hit by no JS; `REFORMAT_PROMPTS` is only reachable via the dead `mode` param of `reformat_text`. — **fix:** delete the legacy endpoints, `REFORMAT_PROMPTS`, the `mode` param, and `api.selectMode` (confirm the tray's `reformat_mode`/`reformat_enabled` reads at `main.js:1438` first).
- `backend/landa_lexicon.py` (424 LOC), `apply_lexicon_correction` (`:1492`, wired into both transcription paths at `:2025`/`:2140`), `tools/build_lexicon_de_medical.py` (311 LOC), `backend/tests/test_lexicon.py` — a fully-built, hooked-in feature **unreachable by users**: `active_lexicons` (default `[]`, `:171`) is only ever read (`:1452`), never written by any UI/endpoint, so `apply_lexicon_correction` always no-ops. Per project notes lexicons are off the roadmap, yet ~750 LOC + the only test suite + two live call sites remain. — **fix:** move the module/tool/tests to `archive/` and drop the two dead call sites; record in `STRATEGY.md`.
- `renderer/settings.js` (3176 LOC) mixes ≥6 responsibilities (i18n ~362, shortcut capture 984, LLM config 1750, linked-apps popup 2225, history 2725, home stats 3080) in one editing hotspot. — **fix:** split along the existing seams (`settings.modes.js`, `settings.llm.js`, `settings.history.js`, `settings.shortcuts.js`, shared `settings.i18n.js`).
- `backend/landa_core.py:1199` — `paste_text` is ~130 lines with the whole Windows clipboard + `SendInput` ctypes implementation (struct defs, `OpenClipboard`, key synthesis) inlined in the `win32` branch; the macOS branch is 6 lines. — **fix:** extract `_paste_windows()` / `_paste_macos()` so `paste_text` is a thin dispatch.

### Low (polish)
- `main.js` has 33 `console.log` calls alongside the structured `logEvent`/`appendLog` facility (`:41-59`). — **fix:** route main-process diagnostics through `logEvent` (or drop them).
- `backend/tests/__pycache__/` and `backend/dist/` clutter the working tree during onboarding. — **fix:** confirm both are gitignored; add if missing.
- `README.md:14` says "Python 3.9+" while the venvs/`landa_backend.spec` target 3.11. — **fix:** align the README floor with the actual interpreter.

## UX

### High (blocks users or fails accessibility minimum)
- `renderer/settings.html:29-89`, `renderer/settings.js:790-799` — Primary sidebar nav items are click-only `<div>`s with no `role`, `tabindex`, or keyboard handler. Keyboard/screen-reader users cannot reach Home/Profiles/Settings/History/Vocabulary/Feedback. — **fix:** make them `<button>` (or `role="tab"` + `tabindex="0"` + Enter/Space); expose active state via `aria-current`/`aria-selected`.
- `renderer/settings.js:986-991` — Shortcut badges that start key-capture are click-only `<div>`s with no keyboard affordance, so a keyboard user cannot rebind any shortcut. — **fix:** make the badge a focusable `<button>` with an accessible name, start capture on Enter/Space.
- `renderer/settings.css` (no `:focus-visible` anywhere; `outline:none` at `828,1694,1846,2357`) — Inputs/search remove focus outline without replacement; keyboard focus is invisible app-wide. — **fix:** add a visible `:focus-visible` indicator (e.g. `box-shadow: 0 0 0 2px var(--primary)`) on all interactive elements.
- `renderer/settings.js:1339-1344,1498-1503` — Model/LLM download errors render raw backend error text: `${t('local.download_failed')}${status.error}`. — **fix:** show a fixed human-readable message, keep raw `status.error` in logs only.
- `renderer/settings.js:2743-2766` — History tab has no loading and no error state: shows the "No transcriptions yet" placeholder while loading, and on fetch failure falls back to `[]`, masking the error as "empty." — **fix:** show a loading skeleton until resolved, and a distinct error state with retry.
- `renderer/update.html` / `renderer/update.js:19-27` — The update window has no error/failure state; a failed download leaves the progress bar frozen with "Downloading update…" and no recovery. — **fix:** add an `onUpdateError` handler with Retry / "Continue using current version."

### Medium (rough edges, polish)
- `renderer/settings.js:2662-2684` — `saveConfig()`/`saveConfigNow()` swallow save failures (no `catch`); a failed persist gives no feedback and silently loses the change. — **fix:** non-blocking error toast with retry.
- `renderer/settings.html:330-349`, `renderer/settings.js:862-879` — The recording-style segmented control is `role="radiogroup"`/`role="radio"` but has no roving `tabindex` or arrow-key handling, so it doesn't behave as the ARIA pattern promises. — **fix:** implement roving tabindex + arrow-keys, or drop the radio roles and label it a button group.
- `renderer/settings.js:2238-2262` — The "Linked apps" modal closes on Escape but has no focus trap, doesn't move focus in on open or restore on close, and lacks `role="dialog"`/`aria-modal`. — **fix:** add dialog semantics, focus first control, trap Tab, restore focus to trigger.
- `renderer/settings.js:2350-2363` — Vocabulary "from/to" inputs rely on placeholders only, no `<label>`/`aria-label`. — **fix:** add `aria-label` ("Misheard word", "Replace with").
- `renderer/onboarding.css:281` — Training-step contenteditable sets `outline:none` and onboarding pills/buttons have no `:focus-visible`. — **fix:** add focus-visible indicators to onboarding controls.
- `renderer/recording.css`, `onboarding.css:120-126,499-506`, `settings.css` — None of the in-app renderers honor `prefers-reduced-motion` (rainbow `halo-spin`, `pulse`, `spin`, `ob-fade-in`, infinite `ob-btn-pulse`). The website respects it (`website/style.css:66`) but the apps don't. — **fix:** wrap looping animations in `@media (prefers-reduced-motion: no-preference)`.
- `renderer/settings.css` (many lines: `267,349,402,491,492,616,996,1045,1671,1814,1921,2073,2095,2151,2271-2281,2385,2537,2544`) — Numerous hardcoded hex that bypass design tokens (`#1d1d1f` vs `var(--text)`; three different destructive reds `#ff3b30`/`#e74c3c`/`#e53e3e` with no shared token; `#5978aa` vs `var(--secondary)`). Several won't adapt in dark mode. — **fix:** replace with tokens; add a `--danger` token to DESIGN.md.
- `renderer/onboarding.js:34-36,71-73` — Language microcopy is alarming ("Landa only understands you in German."). For a changeable setting it reads as a warning. — **fix:** reframe positively ("Landa will transcribe German.").

### Low (cosmetic)
- `renderer/settings.html:96,105` — `home-bg-sky.jpg` / `icon.png` have no `width`/`height`; causes layout shift on slow loads. — **fix:** set intrinsic dimensions or reserve space.
- `website/index.html:230-267` — Three demo `.mp4`s (one 7.5 MB) autoplay with no dimensions and the largest has no `preload="metadata"`; heavy mobile first-paint + CLS. — **fix:** add dimensions, `preload="metadata"` on the larger video.
- `renderer/onboarding.html:32-33` — UI-language pills ("Deutsch"/"English") lack a selected `aria-pressed` state. — **fix:** add `aria-pressed` reflecting selection.
- `renderer/settings.html:364,446` — The reset `↺` glyph buttons rely on `title` only (not reliably exposed to AT). — **fix:** add `aria-label="Reset to default"`.

**Recommended next step:** Lock down the localhost backend — add a per-launch bearer token + `Origin`/`Host` check on all routes (`landa_core.py:2903-2935`) — which simultaneously closes the highest security finding (API-key exfiltration) and forces the config-mutation path through a single guarded entry point you can then put a lock behind (the #2 reliability race).
