## Top-line findings

Ranked across all dimensions.

1. **[Security/Critical] [backend/landa_core.py:2594](backend/landa_core.py#L2594)** — Flask backend has no auth, no CSRF protection, and no Host-header validation; any local process or web page can hit `GET /config` to exfiltrate plaintext API keys, `POST /start` to silently activate the mic, or `POST /config` to overwrite all settings. DNS rebinding makes this a remote attack.
2. **[Security/High] [backend/landa_core.py:312-315, 337-340](backend/landa_core.py#L312-L315)** — `config.json` and `history.json` (storing API keys and every transcription) are written with `0644` — readable by any other user on the machine.
3. **[Security/High] [main.js:726-939](main.js#L726)** — all four `BrowserWindow` instances missing `sandbox: true`; no `setWindowOpenHandler`/`will-navigate` lockdown anywhere in the app.
4. **[Reliability] [main.js:1071-1077](main.js#L1071-L1077) + [backend/landa_core.py:312-315](backend/landa_core.py#L312-L315)** — backend killed with default SIGTERM and no wait on quit; combined with non-atomic `save_config`/`_save_history`, a quit during a write truncates `~/.landa/config.json` and the next launch silently rewrites it with `DEFAULT_CONFIG`, wiping every user setting.
5. **[Reliability] [main.js:1048-1069](main.js#L1048-L1069)** — backend has no restart-on-crash and no port-conflict check; once the Python process dies (or a stale one is bound to 7890), the tray looks idle but every hotkey silently fails forever.

8. **[Performance] [main.js:949-958](main.js#L949-L958) + [main.js:143-182](main.js#L143-L182)** — `/audio-level` polled at 12.5 Hz over a fresh TCP connection per call (no shared `http.Agent` keepalive), with no in-flight guard; under any backend stall, dozens of requests pile up.

10. **[Maintainability] [renderer/settings.js:12-20](renderer/settings.js#L12-L20) + [backend/landa_core.py:112-173](backend/landa_core.py#L112-L173) + [main.js:1743-1745](main.js#L1743-L1745)** — DEFAULT_CONFIG duplicated in three places and already drifting (`llm_provider` defaults disagree between Python and renderer).

## Reliability

### Critical (will cause data loss, hangs, or crashes in production)
- `main.js:1071-1077` — `stopBackend()` sends only the default SIGTERM (`backendProcess.kill()`) and never waits for exit. On `will-quit` (`main.js:1763-1768`) Electron then exits immediately, leaving the Python backend (PyInstaller binary) to be reaped by the OS. If the backend is mid-write to `~/.landa/config.json` or `history.json` it can be killed mid-fsync and leave a truncated/empty JSON that `load_config()` (`backend/landa_core.py:294-309`) will silently overwrite with `DEFAULT_CONFIG`, losing all user settings. **fix:** in `stopBackend()` send SIGTERM, `await` `'exit'` with a 2-3s timeout, then SIGKILL; do the wait in a `before-quit` hook with `event.preventDefault()` so Electron doesn't tear down first. On Windows, Node's `kill()` maps to `TerminateProcess` (no graceful shutdown at all) — register a SIGINT handler in the backend (`signal.signal`) and use `taskkill /pid` to deliver CTRL_BREAK so Flask can drain.
- `main.js:1048-1069` / `main.js:1763-1768` — backend has no restart-on-crash. If `landa_backend` exits non-zero (OOM, segfault in PyAudio, exception in Flask thread), `backendProcess` is set to `null` and nothing ever respawns. The tray will continue to look idle but every hotkey press silently fails (every API call rejects, the catches at `main.js:345` and `main.js:355` swallow the error). **fix:** in the `exit` handler, if the app isn't quitting and exit code != 0, schedule `startBackend()` with exponential backoff (cap at 3 attempts/30s) and surface a tray-status indicator after the cap.
- `main.js:1048` — backend spawn never checks port 7890 availability. If a stale `landa_backend` process from a previous crash is still bound, Flask `app.run` (`backend/landa_core.py:2594`) will throw `OSError: [Errno 48] Address already in use` and the new backend exits immediately; the Electron app then hangs forever in "no backend" mode (api timeouts every 5-12s, no recovery). **fix:** in `startBackend()` probe `127.0.0.1:7890` first; if occupied and unreachable from our process, kill the orphan (use `lsof -ti:7890` on macOS / `netstat -ano | findstr :7890` on Windows) before spawning.
- `main.js:302-363` — the recording window's "processing" spinner only clears when `setRecordingState(false)` runs, which depends on `api.fetchStatus()` succeeding (`main.js:352-356`). If the backend dies *after* `recording-processing:true` is sent (`main.js:329`) and before/while `/stop` finishes, both `stopRecording()` and `fetchStatus()` reject — the catch at `main.js:355-357` keeps current state, so `isRecording` stays `true`, the recording window stays visible, and the spinner spins forever. The status poll at `main.js:1149-1178` won't recover either because every call throws and is silently caught. **fix:** when the inner stop/start call throws, force `setRecordingState(false)` and `recordingWindow.webContents.send('recording-processing', false)`; surface a tray error state so the user knows transcription was lost.
- `backend/landa_core.py:312-315` — `save_config()` writes `config.json` non-atomically. If the backend is killed mid-write (see Critical #1) the file is truncated and the next `load_config()` (`landa_core.py:300-302`) catches `JSONDecodeError` and calls `save_config(DEFAULT_CONFIG)`, silently destroying every user setting (hotkeys, vocabulary, modes, API keys). Same defect in `_save_history()` (`landa_core.py:337-340`) and the whisper download tmp paths are atomic but the JSON state files aren't. **fix:** write to `config.json.tmp` then `os.replace()` to `config.json`. On read, if JSON is invalid, prefer keeping a `.bak` copy rather than overwriting with defaults.
- `main.js:1424-1433` — `save-config-sync` IPC writes `config.json` from the renderer with `fs.writeFileSync` (also non-atomic) AND fires `api.saveConfig(cfg)` async. If the user closes Settings, the sync write wins, but the async POST to backend can race — the backend may receive a stale POST after writing newer config to disk, and on next load the backend's `save_config()` (called from POST handler at `landa_core.py:2202`) overwrites the renderer's just-written file. **fix:** make the sync path go through the backend (don't write directly from main process); or make `save_config` atomic and serialize POST/disk writes via a single owner.
- `backend/landa_core.py:1247-1288` — `_finalize_then_teardown` runs in a daemon thread (`landa_core.py:1284`). On process exit (Critical #1), daemon threads are killed without finishing — a stop initiated milliseconds before quit drops the transcription, the paste never happens, and the user has no idea their dictation was lost. **fix:** make the teardown thread non-daemon and register `atexit`/SIGTERM handler that joins it with a sane timeout; surface failures.

### High (degraded behavior under load or partial failure)
- `main.js:949-958` — `audioLevelTimer` polls `/audio-level` every 80ms with the default 5s timeout. If the backend stalls (mlx-lm load, sd.query_devices block) requests pile up: at 80ms cadence and 5s timeout, up to ~62 inflight HTTP requests can stack in Node's agent pool. Each `apiRequest` creates a new `http.request` with no shared agent and no AbortController, so backpressure has no escape valve. **fix:** track in-flight; skip the next tick if previous hasn't returned. Use a tighter 500ms timeout for audio-level since stale data is useless.
- `backend/landa_core.py:2232-2246` — `/stop` blocks the request thread on `_transcription_ready.wait(timeout=30)`. Flask is `threaded=True` (`landa_core.py:2594`) using the dev server, which spawns one OS thread per request and has no pool cap. Multiple rapid stop+start cycles, plus the always-on 80ms `/audio-level` poll and 1s `/status` poll, can spawn unbounded threads. **fix:** front the backend with a real WSGI server (waitress on Windows, gunicorn on macOS) with a fixed worker pool, or at minimum cap threads.
- `main.js:143-182` — `apiRequest` has no retry logic and no circuit breaker. Every poll tick (`/status` every 1s, `/audio-level` every 80ms during recording) opens a fresh TCP connection to localhost (no `http.Agent` keepalive). Under a flapping backend this causes a thundering herd of connection attempts. **fix:** share an `http.Agent({ keepAlive: true })`; when 3 consecutive polls fail, back off the poll interval until success.
- `main.js:1734-1751` — `applyConfig()` is delayed 2000ms after `whenReady`. During that 2s window: hotkey press hits `handleHotkeyPress` (`main.js:302`), but `currentShortcut` is null so the hotkey isn't even registered — there's a hard window where the user can't dictate. The fallback at `main.js:1743-1745` only fires if `getBestAvailableConfig()` *fails* — but if it returns config slowly the fallback never registers, and actual config registration happens late. **fix:** register the hotkey from disk synchronously before `setTimeout`; or block on `getBestAvailableConfig` (with a 2s timeout) before the rest of init.
- `backend/landa_core.py:69-101` — `_load_pricing()` calls `urllib.request.urlopen(PRICING_URL, timeout=3)` synchronously on first cost calculation. This runs inside the request-handling thread of `/stop`, adding up to 3s to the user-perceived dictation latency on first use after pricing TTL expires. **fix:** prefetch on backend startup in a thread; never let pricing fetch block the transcription path.
- `main.js:1149-1178` — status poll never times out individually beyond the 5s default in `apiRequest`. If `/status` hangs (backend deadlock from a stuck PortAudio teardown — `landa_core.py:1140-1147`), the poll lets the next tick fire before the previous returns (no in-flight guard), so multiple `setRecordingState` calls can race and overwrite each other. **fix:** track in-flight like the audio level path needs, and use a short (1s) timeout.
- `main.js:1764` — `globalShortcut.unregisterAll()` runs on `will-quit`, but if the app is force-quit (Cmd+Q during a hung quit, or OS power-off), shortcuts can persist in Electron's table until app restart. Combined with single-instance lock (`main.js:1707`), a stale lock file blocks restart. **fix:** on `requestSingleInstanceLock` failure, the second instance signals the first via `second-instance` (already wired) but still calls `app.quit()` — verify the first responds; if not, surface a "already running" dialog.
- `preload.js:90-92` — `onAudioLevel` does NOT call `removeAllListeners('recording-level')` before adding the handler (unlike every other `on*` method). If the recording renderer is reloaded (hot-reload, BrowserWindow recreate), each call accumulates a listener — every audio-level IPC fires N callbacks, each rewriting the same DOM. **fix:** add `ipcRenderer.removeAllListeners('recording-level')` to match the pattern.
- `backend/landa_core.py:1607-1613` — whisper download writes to `dest.with_suffix('.bin.tmp')` and atomically renames on success; good. BUT the Windows path (`landa_core.py:1614-1633`) uses `snapshot_download` directly into `dest_dir` with no tmp dir — if the download is interrupted, `is_whisper_model_cached` (`landa_core.py:1583`) returns True if `model.bin` exists, even partially. **fix:** download into a sibling tmp dir, rename on success.
- `main.js:1457-1499`, `:1508-1543`, `:1557-1592` — three near-identical SSE parsers for nemo/whisper-deps/llm-deps install streams. Each silently swallows backend connection drops via `req.on('error', resolve(...))` — but a half-installed pip package silently leaves `is_xxx_deps_installed` returning False with no useful diagnostic. The 10-min timeout (`landa_core.py:1465`) on a real network blip kills the install with no retry. **fix:** factor into one helper; surface stderr on close; handle partial drops by resuming or warning.
- `main.js:78-137` — auto-updater has no retry on transient network failures. If `downloadUpdate` fails mid-download, `destroyUpdateWindow()` runs and `updateDialogShown` resets, but the user has to manually restart to retry. Worse — if `update-downloaded` fires but `quitAndInstall` (`main.js:130`) silently fails (e.g., `app.asar` lock on Windows, codesign mismatch on macOS), the user is stuck with the update window showing "Installing" forever. **fix:** add a 30s timeout on `update-installing` IPC; if no quit happens, show an error and offer manual restart.

### Medium (resilience gaps)
- `backend/landa_core.py:2168, 2594` — running Flask's dev server in production (`app.run`). Flask logs warnings about this; under load it doesn't drain cleanly on SIGTERM and tracebacks leak via 500. **fix:** use waitress (cross-platform).
- `main.js:1052-1057` — backend stdout/stderr both go to `console.log` with no file logging. After ship, when a user reports "transcription stopped working" there's no log to inspect. The Electron main process logs are also not persisted to disk. **fix:** route both backend and main `console.*` to a rotating file in `app.getPath('logs')`; expose a "Show Logs" tray item.
- `main.js:78-137` — `setupAutoUpdater` is only set up if `app.isPackaged` (`main.js:1755`), but `autoUpdater.on('error', ...)` only logs to console. If signature verification fails, the user sees no notification. **fix:** show a non-blocking dialog (or tray badge) on persistent updater errors.
- `main.js:1758` — hourly auto-update check uses `setInterval` with no `clearInterval` on quit. Combined with the auto-updater's own internal state, this can keep timers alive after the app's `will-quit`. **fix:** save the interval id and clear it in `will-quit`.
- `backend/landa_core.py:1944-1960` — `_get_llm_model` silently catches every exception and returns None (model-load failure becomes a silent no-op). Combined with `reformat_text_local` callers, the user sees "raw transcription" with no hint that the LLM crashed. **fix:** surface load errors via a dedicated status endpoint or sticky error in `_llm_download_state`.
- `backend/landa_core.py:1141-1147` — when previous teardown is still running, `start_recording` returns `False` and the user just sees nothing happen. Electron's `handleHotkeyPress` (`main.js:341-344`) treats `await api.startRecording()` as success regardless of returned `started: ok` field (`landa_core.py:2229`). **fix:** Electron should check `started`/`stopped` flags and surface a tray notification on failure.
- `main.js:177-181` — `req.write(JSON.stringify(body))` runs `JSON.stringify` twice (also at line 156 to compute `Content-Length`). For a large config payload this doubles serialization cost. **fix:** stringify once, reuse.
- `backend/landa_core.py:323-355` — `_history_lock` is held during JSON read+write, but the file isn't fsynced. A crash mid-write corrupts history (caught by `_load_history`'s except block which returns []). **fix:** atomic write via tmp+rename.
- `backend/landa_core.py:642-677` — `httpx.post` to `LANDA_PROXY_URL` has a 15s timeout and no retry. A transient 503 from the proxy silently falls back to raw text — the user gets an unformatted transcription with no indication that the LLM step failed. **fix:** retry once on 5xx with backoff; log to history usage that reformat was skipped.
- `main.js:1186-1196` — `requestPermissions()` only requests microphone on macOS. On Windows, the app relies on `getUserMedia` from onboarding (`renderer/onboarding.js:144`) but if onboarding is skipped (existing user), there's no Windows mic prompt at all — recordings will fail silently. **fix:** explicitly trigger Windows mic on first `start_recording` failure with a helpful dialog.
- `main.js:130-131` — `setTimeout(() => autoUpdater.quitAndInstall(), 600)` — 600ms is arbitrary. If user is mid-recording, the quit drops the transcription. **fix:** check `isRecording` and defer install until idle, or warn the user.
- `main.js:1763` — no `before-quit` handler. If a quit is initiated via tray menu while a `/stop` is in flight (waiting up to 35s for transcription), the user gets `app.quit()` (`main.js:679`) which kills Electron immediately, killing the in-flight transcription. **fix:** in `before-quit`, if `isRecording` or `hotkeyInFlight`, `event.preventDefault()` and wait for completion (or a short timeout).
- `backend/landa_core.py:1370-1418` — realtime path's hallucination filter and pipeline are duplicated from `_transcribe_and_paste`. If one is updated and the other isn't, behavior diverges. **fix:** factor into a single post-pipeline helper.

## Performance

### Critical (user-visible jank, hangs, or OOM in normal use)
- `main.js:949-958` — `startAudioLevelPolling` runs `setInterval` at **80ms** (12.5 Hz) firing an HTTP `GET /audio-level` per tick to a Flask app, with each response triggering an IPC `webContents.send` to the recording window. Each request opens a fresh TCP connection (no `http.Agent({ keepAlive: true })`, see `apiRequest` at `main.js:143-182`), runs through Python's WSGI dispatch, and returns 25 bytes of JSON. Over a typical 30-second recording that's ~375 round-trips. — **fix:** switch to push: have the backend stream levels via SSE/WebSocket, or hold the connection open with long-poll. At minimum, raise a single keep-alive `http.Agent` and reuse it across all `apiRequest` calls; bump the interval to 100ms and align with the bar `transition: transform 90ms ease` in `recording.css:79` so animations remain smooth.
- `main.js:1424-1433` — `save-config-sync` is a synchronous IPC + `fs.writeFileSync` of the entire config on `beforeunload` (`renderer/settings.js:413-423` flushes on every window close). The renderer blocks completely until `JSON.stringify` + disk fsync finish. With a config that contains 30k+ vocabulary entries this hangs the close. — **fix:** make the unload save async with an `event.preventDefault()` short delay, or persist on every change so unload doesn't need a flush.
- `backend/landa_core.py:343-354` — `add_history_entry` calls `_load_history()` (full JSON parse) + `_save_history()` (full rewrite with `indent=2`) on **every transcription** while holding `_history_lock`. After 30 days the history file grows unboundedly; each new entry parses and rewrites the whole file on the paste-critical path right after `paste_text`. At 1k entries each ~500 bytes this is already ~500 KB rewritten per recording. — **fix:** cap history at N entries (e.g. 500), keep an in-memory list, append-only on disk, or write asynchronously off the paste path.
- `backend/landa_core.py:2567-2569` — `GET /history` re-reads and parses the JSON file from disk on every call; `renderer/settings.js:380` invokes it on every history-tab click and on every `history-updated` event. Combined with unbounded growth this becomes a multi-MB parse per click. — **fix:** cache parsed history in memory; invalidate on write; or paginate.

### High (degrades meaningfully at moderate scale)
- `main.js:143-182` — `apiRequest` creates a fresh `http.request` per call with no shared `http.Agent`, so every call (status poll at 1 Hz, audio level at 12.5 Hz, every IPC handler) opens and tears down a TCP connection to localhost. — **fix:** create one `new http.Agent({ keepAlive: true, maxSockets: 4 })` at module load and pass it in `options.agent`.
- `main.js:1149-1178` — `startStatusPolling` runs a `GET /status` every 1 s for the entire app lifetime even when the user isn't recording and no settings/recording window is open. Each call wakes Flask, awakens the renderer if the window exists, and triggers `updateTray()` rebuilds. After 30 days of uptime that's 2.6M requests. — **fix:** stop polling when no UI window is open; rely on hotkey-triggered state syncs only, or push status from backend over a single SSE channel.
- `main.js:686-697` — `updateTray()` (called from polling, mode changes, theme updates, recording state) rebuilds the entire context menu (`Menu.buildFromTemplate`) and re-creates the tray image with `nativeImage.createFromPath` from disk every time. The tray icon files are read repeatedly with no cache. — **fix:** load the two tray icons once at startup into module-level variables; only rebuild the menu when `modesConfig`/recording state actually changes (memoize last-built menu by signature).
- `main.js:1212-1247` (`getInstalledAppsMac`) — for every `.app` in `/Applications` (typically 80+), forks `sips` to convert an .icns to PNG, writes a temp file, reads it back, and unlinks. Even with `Promise.all` this spawns 80+ subprocesses simultaneously; `getInstalledAppsWin` (`main.js:1332-1341`) walks them sequentially with `await app.getFileIcon` per binary. Triggered eagerly via `preloadInstalledApps()` at `renderer/settings.js:467` on every settings-window open. — **fix:** persist the icon cache to disk (data URLs by path+mtime); only rebuild entries whose mtime changed; defer first scan until the popup is opened.
- `main.js:1135-1153` — `JSON.stringify(newModes) !== JSON.stringify(modesConfig)` compares config by serializing twice on every `applyConfig` (which runs on every poll if config came from poll, every IPC patch, and at every theme change). For deep configs this is O(n) per second. — **fix:** structural compare or version counter from backend.
- `main.js:1716-1761` — `setupAutoUpdater` schedules `setInterval(... 60 * 60 * 1000)` (hourly update check) but never clears it on quit (only `pollTimer` is cleared at `main.js:1765`). Not a leak in practice but a forgotten timer; bigger issue is `autoUpdater.checkForUpdates()` runs immediately on launch racing with backend startup. — **fix:** clear in `will-quit`.
- `renderer/settings.js:467` — `preloadInstalledApps` runs at every settings-window open (`DOMContentLoaded`); the cache is renderer-only so it dies with the window and the heavy mac/win scan repeats every time the user reopens settings. — **fix:** move the cache into the main process so it survives window close (the IPC handler already sees the request — store `installedAppsCache` in `main.js`).

### Medium (wasted work, modest impact)
- `main.js:1052-1057` — `backendProcess.stdout/stderr.on('data', ...)` calls `data.toString().trim()` and `console.log`s every chunk for the lifetime of the backend. After 30 days of verbose Python logging this is significant CPU + buffer growth on the main process. — **fix:** gate behind `if (!app.isPackaged)` or a debug flag; pipe to a rolling log file in production.
- `main.js:202-210` — `readConfigFromDisk` uses `fs.readFileSync` then `JSON.parse` synchronously; called from `is-dev-mode` IPC handler (`main.js:1620-1624`) which the renderer can invoke at any time, blocking the main process. — **fix:** cache the dev-mode flag on startup or use `fs.promises.readFile`.
- `main.js:23-41` — startup `.env` parse uses sync `existsSync` + `readFileSync` + regex split; minor, only dev-mode but it blocks before window creation.
- `main.js:583-588` — `createTray` calls `fs.existsSync` then loads the icon via `nativeImage.createFromPath`. Combined with `updateTray` re-creating images per call, this is repeated disk I/O. — **fix:** load once into a module-level `nativeImage`.
- `renderer/settings.js:2393` — `renderHistory` calls `list.querySelectorAll('.history-entry').forEach(el => el.remove())` then re-builds every entry from scratch on every history update, including invalidations triggered by `history-updated` IPC events. With unbounded history, every new transcription triggers a full re-render of every entry. — **fix:** prepend the new entry; only full-render when the user explicitly clears.
- `renderer/settings.js:2410-2456` — each rendered history entry attaches three event listeners directly to its DOM nodes (`copy`, `delete`, `mouseenter`/`mouseleave`). For long histories (>100 entries) this is hundreds of listeners per render. — **fix:** delegate via a single listener on `#history-list` matching `.copy`/`.delete`.
- `renderer/recording.js:26-31` — `onAudioLevel` writes each bar's `transform` directly inside the IPC callback (no `requestAnimationFrame` batching). ## Security

### Critical (exploitable now, immediate risk)
- `backend/landa_core.py:2594` — Flask backend binds to `127.0.0.1:7890` with **no authentication, no Host-header validation, and no CSRF protection** on any endpoint; any local process or any remote web page (via DNS rebinding or simple `<form>` POST) can hit `POST /start`/`/stop` to silently start the mic and paste arbitrary transcribed text into the focused app, `GET /config` to exfiltrate the user's plaintext OpenAI/Anthropic `api_key` + `llm_api_key` (lines 2171-2173), `POST /config` to overwrite hotkeys/provider/keys, or `DELETE /history` to wipe data — **fix:** require a per-launch random bearer token shared between Electron and the backend (pass via env/argv at spawn), validate it on every request, and reject requests whose `Host` header isn't `127.0.0.1:7890` or `localhost:7890`.
- `backend/landa_core.py:2179, 2293, 2304, 2447, 2551` — every state-changing endpoint uses `request.get_json(force=True)` with no origin/CSRF check; a cross-origin `fetch` with `Content-Type: text/plain` (or a form POST) can trigger `POST /start`, `/stop`, `/cancel`, `/modes/select`, `/reformat`, etc., from any opened webpage — **fix:** add the bearer-token check above and refuse simple-CORS POSTs without it.

### High (likely exploitable or sensitive data exposure)
- `package.json:73-75` (Electron `^33.0.0`) — `npm audit` reports high-severity Electron advisories applicable to this version (use-after-frees in PowerMonitor, fullscreen permission callbacks, offscreen paint, download dialog, header injection, etc.) — **fix:** bump to the latest Electron 33.x patch or move to Electron 38+ and rerun `npm audit`.
- `package.json:41-44` + `.github/workflows/release.yml:69-78` — Windows installer is **unsigned**: no `certificateFile`/`signtoolOptions`, no `publisherName` set, so `electron-updater`'s Windows signature check is a no-op and update integrity reduces to "whoever can write to the GitHub release can push RCE to every Windows user" — **fix:** sign the Windows installer (Authenticode) in CI and set `verifyUpdateCodeSignature: true` + `publisherName` in `build.win`.
- `backend/landa_core.py:312-315, 337-340` — `~/.landa/config.json` (stores plaintext `api_key`, `llm_api_key`) and `~/.landa/history.json` (stores every transcription, often containing passwords or private content) are written with default `0644` permissions — readable by any other user on the machine — **fix:** `os.chmod(path, 0o600)` after each write and `CONFIG_DIR.chmod(0o700)` on creation.
- `main.js:726-739, 766-782, 802-828, 910-928` — none of the four `BrowserWindow` instances set `sandbox: true`; combined with the full `contextBridge` surface (which can drive `pip install` via `installLlmDeps`/`installWhisperDeps` and trigger arbitrary backend operations), any renderer-side code execution gets an inflated capability — **fix:** add `sandbox: true` to every `webPreferences` block; the preload already uses only `ipcRenderer` so no code change is needed.
- `main.js` (no `setWindowOpenHandler` or `will-navigate` handler anywhere) — there's no global navigation lockdown; if any renderer code (or an XSS via unescaped URL/app-name sinks) opens `window.open` or sets `location`, Electron will navigate the renderer to attacker-controlled origins inside a context with the full preload API — **fix:** for every BrowserWindow, register `webContents.setWindowOpenHandler(() => ({ action: 'deny' }))` and `webContents.on('will-navigate', e => e.preventDefault())`.
- `renderer/recording.html` and `renderer/update.html` — neither file has a `Content-Security-Policy` meta tag (settings.html and onboarding.html do); any future injection has no script-src floor — **fix:** add the same `default-src 'self'; ...` CSP meta tag used in settings.html.

### Medium (defense-in-depth)
- `renderer/settings.js:2014, 2098, 2100, 1957, 1975, 1979` — user-controlled `url` strings (from the linked-URLs popup) and app `name` strings (from the linked-apps list) are interpolated into `innerHTML`/`title`/`data-name`/`src` via template literals with no escaping; a value like `x.y"><img src=x onerror=...>` round-trips through config and executes on next render — **fix:** wrap every untrusted interpolation with the existing `escapeHtml()` helper.
- `main.js:1237, 1263` — `execAsync(\`sips ... "${icnsPath}" --out "${tmpPng}" ...\`)` and `execAsync(\`plutil -convert xml1 -o - "${plistPath}"\`)` build shell strings from `/Applications/<bundle>.app` paths; an `.app` whose name contains `"` or `` ` `` causes shell injection — **fix:** switch to `execFile`/`spawn` with an argv array (no shell) for `sips` and `plutil`.
- `main.js:79, 125-132` — `electron-updater`'s GitHub provider does not enforce monotonic versions; if an attacker tampers with `latest-mac.yml`/`latest.yml` they can downgrade users to an older signed-but-vulnerable version — **fix:** refuse `info.version <= app.getVersion()` in the `update-available` handler before calling `downloadUpdate()`.
- `backend/landa_constants.py` + `scripts/before_build.js:22-30` — `LANDA_APP_SECRET` is baked as a literal string into the PyInstaller binary; anyone who installs Landa can `strings` it out and call the proxy directly — **fix:** treat the proxy's IP rate limit as the only meaningful defense and rotate the secret periodically; at minimum, ensure the local `.env` value is not the same as production.
- `backend/landa_core.py:84-101` — pricing JSON cache `~/.landa/model_pricing.json` inherits default `0644` perms with no signature check — **fix:** `chmod 0600` alongside the config/history fix above.
- `backend/landa_core.py:2340, 2425-2426, 2515-2531` — `/nemo/install`, `/whisper-local/install-deps`, `/llm-local/install-deps` all shell out to `pip install` of hardcoded packages, reachable by the unauthenticated localhost API; combined with the Critical CSRF/no-auth issue, a malicious page can trigger repeated `pip install` jobs saturating disk/network — **fix:** subsumed by adding bearer-token auth on all endpoints.

### Low
- `main.js:1052-1057` — backend stdout/stderr is logged verbatim via `console.log('[backend] ...')`; `landa_core.py` prints transcribed text at lines 626/664/707/731/1761 — sensitive content lands in Electron's stderr and any system log capturing it — **fix:** truncate content snippets in production builds.
- `backend/landa_core.py:1424` — the `/reformat` endpoint writes user-supplied `text` into the LLM provider request without length limits; an unauthenticated caller can drive arbitrary spend through the user's API key — **fix:** subsumed by the auth fix; also add a `len(text)` cap.
- `entitlements/entitlements.mac.plist` — grants `com.apple.security.cs.allow-jit` and `com.apple.security.cs.allow-unsigned-executable-memory` app-wide; only the PyInstaller binary needs them — **fix:** apply them only to the bundled backend via a child entitlements file.
